Recommended flow

Five states, one irreversible decision

Only the output contract is permanent. All creative choices stay fluid, and the user sees the consequence before creation.

01Add comp

Open the existing creation surface from the composition rail.

02Choose Generate

Keep Generate alongside Edit, Moodboard, 3D, and other composition families.

03Pick output

Require an explicit Image, Video, or Audio selection. Do not preselect.

04Set starting values

Name, same-type model, and type-specific defaults. Show the lock before Create.

05Work freely

Change model, desired dimensions, output framing, inputs, settings, and takes—within the locked media type.

Behavior & data contract

Make type stability structural

The Studio guardrail is helpful, but the source schema and runtime must remain authoritative when recipes are edited by hand or by agents.

RULE 1 Comp owns output

Add a required output field to generative recipe data. Build the composition descriptor and media element from that value, never from the selected model.

  • output is written at creation and excluded from normal recipe patch operations.
  • Desired width and height belong to the comp but remain editable; they are not part of the immutable media-type lock.
  • Changing output means “Duplicate as Image / Video / Audio,” creating a new identity.
  • Image comps expose one frame; edit placement owns how long the still is held.

RULE 2 Model must match

Filter the picker only by model.output === recipe.output, then repeat that type assertion in runtime update and generation submission paths. Geometry and timing never participate in model visibility.

  • A hand-authored mismatch produces a typed “model does not produce video” diagnostic.
  • Every same-output model remains visible regardless of current width, height, aspect, resolution, or duration.
  • When a selected model does not support a current value, keep the model selected and show an inline value warning with supported choices; do not hide the model or silently rewrite the recipe.
  • Changing model never deletes inputs; incompatible roles are marked and block Generate.
  • Historical takes with a different kind remain viewable/downloadable but cannot be pinned.

RULE 3 Normalize model output inside the comp

The comp owns editable desired dimensions independently of the model’s native take dimensions. A local output transform turns the immutable raw take into the published comp output.

  • Changing desired dimensions, crop, position, matte, or local resize rebuilds only a derived artifact; it never resubmits the creative generation.
  • AI upscale, when chosen, is an explicit separate derivative job with its own cost and provenance—not a hidden generation side effect.
  • Keep raw take download/preview available alongside the normalized comp output.
  • Store crop regions in normalized coordinates so they survive raw resolution changes; the first version uses one spatial crop for the full video.
  • Use separate hashes: the provider-generation hash covers model request settings, while the presentation hash covers raw take + desired dimensions + output transform.

RULE 4 Input adaptation belongs to the edge

The source comp remains untouched. Each consumer stores how it wants to use that source, so the same portrait image can be cropped in one recipe, letterboxed in another, and passed through natively in a third.

INPUT UX Separate type from role

Today image, endImage, video, and audio mix media identity with provider role. Split them conceptually:

  • Media kind is derived from the source comp or asset and cannot be lied about.
  • Role belongs to the consumer: start frame, end frame, style reference, motion reference, or audio guide.
  • On drop, choose the only valid role automatically; ask only when multiple roles are valid.

INPUT FIT Four visual policies

Show policies only for image/video inputs when source and target geometry differ:

  • Source as-is — no preprocessing; default when the provider accepts arbitrary geometry.
  • Crop to fill — preserve aspect, fill target, expose focal point.
  • Fit inside — preserve all content, expose matte color.
  • Stretch — exact target size, explicitly warns about aspect distortion.

SOURCE SHAPE Proposed authored representation

Only media type is immutable. Desired dimensions and output fitting stay editable, and input refs keep their own pre-generation adaptation.

{ "output": "video", // required, immutable "width": 1920, "height": 1080, // desired comp output; editable "model": "seedance-2.0", // may change; must output video "resolution": "720p", // raw model request; affects generation hash "outputFit": { // post-generation; local presentation hash "mode": "cover", "crop": [0.08, 0.12, 0.84, 0.76], "scale": { "method": "lanczos3", "upscale": true } }, "refs": [{ "src": "comp://lighthouse-visitor", // resolves to image "role": "start-frame", // consumer meaning "adapt": { "fit": "cover", "position": [0.5, 0.42], "matte": "#000000" } }] }

Acceptance coverage

What must be true before merge

The invariant should be tested through both Studio interactions and direct runtime calls, because source and agents can bypass the visual picker.

✓
Explicit creation

Create remains disabled until Image, Video, or Audio is deliberately selected.

✓
Stable descriptor

Changing model within the allowed set never changes CompositionDescriptor.outputKind.

✓
Geometry-neutral picker

Changing size, aspect, resolution, or duration never removes a same-output model from either model picker.

✓
Desired output dimensions

The normalized comp artifact exactly matches its editable target width and height, regardless of raw take dimensions.

✓
No paid rerun

Changing crop, fit, matte, or local resize invalidates only the presentation artifact. AI upscale is a separate explicit job and never resubmits generation.

✓
Raw take preservation

Raw provider bytes stay previewable and downloadable after any output-framing changes.

✓
Defense in depth

A cross-type patch, submit, or pin is rejected even when invoked without the Studio UI.

✓
Typed drag/drop

Invalid timeline and generation-input drops refuse before changing source.

✓
Edge-local fit

Two consumers can use the same source with different policies and different artifact hashes.

✓
Legacy safety

Existing recipes gain a deterministic lock; incompatible historical takes remain accessible.

✓
Undoable edits

Model, input role, and adaptation changes use existing source transactions and undo/redo.

✓
Provenance

Generation records preserve raw provider settings; presentation records capture desired dimensions, output transform, and normalized inputs.
